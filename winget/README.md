# Winget manifests

The `RoXimn.Mollana/<version>/` directories hold the three YAML documents
that [`microsoft/winget-pkgs`](https://github.com/microsoft/winget-pkgs)
expects for each released version of Mollana, generated by
`scripts/winget_manifest.py` from `pyproject.toml` and the SHA-256 of the built
installer:

```
uv run python scripts/winget_manifest.py
```

Review the three files — version, SHA-256, release date, asset URL — and
commit them in the same atomic commit as the version bump. The release
workflow runs `--check`, which fails when the committed manifest does not
match the installer CI just built, so a stale manifest cannot ship.

## Submitting to winget-pkgs

The manifests here are not consumed directly; they must be merged into
`microsoft/winget-pkgs` before `winget install RoXimn.Mollana` works.

1. Fork [`microsoft/winget-pkgs`](https://github.com/microsoft/winget-pkgs) and
   clone the fork.
2. Copy `winget/RoXimn.Mollana/<version>/` into
   `manifests/r/RoXimn/Mollana/<version>/` of the fork — the file names stay
   the same; only the directory moves.
3. Open a pull request with just those files. One package version per PR;
   non-manifest changes belong in a separate PR.
4. The CLA bot asks for a signature; the validation pipeline downloads the
   installer and installs it on a Windows runner, reporting the result on the
   PR.
5. Once merged, `winget install RoXimn.Mollana` works for everyone.

Repeat steps 2–5 for every release. The installer URL is stable per version
(`releases/download/v<version>/Mollana-<version>-win64-setup.exe`), which is
what winget requires.
